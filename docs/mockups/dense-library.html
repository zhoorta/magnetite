            Other themes, same layout

            • The dense layout is not a theme. It reads the active theme's colours, font and corner radius, so every bundle in themes.json (and shared ones) works. Use the Theme buttons above the frame.
            • Proportional fonts (Late-night FM, Amber) work too: columns are aligned with tabular numbers and flex, not with character cells.
            • The Terminal theme keeps its square corners and mono font because it asks for them (radius: 0), not because the layout does.

            Covers and meters stay real

            • The cover is the real image by default. The pixelated mosaic is a per-user choice (and the default in the Terminal theme only), because it is a look, not a need.
            • The meters are the existing visualizer canvas, drawn by the engine in its own cell with the theme's look (visualizers: [{id, params}]), and still limited to the meters you chose. The mock only imitates three of them.

            DR and the file truth in the lists

            • Albums show the average DR of their analysed tracks, tracks show their own, with a ! in front when a finding exists (clipping, true peak, a cut-off). Not analysed yet shows a dash.
            • The colour follows App\Support\FileTruth (good, fair, poor), so the page and the TUI never disagree.
            • s sorts by name, year or DR, so the most squashed albums are two keys away. A folder row shows the DR of everything under it.

            Command line

            • : opens one line at the bottom. Try :analyze, :move jazz, :theme paper, :sort dr. Tab completes, Esc cancels.
            • Every command acts on the marked albums, or on the selected row (a folder means all albums in it).
            • The single keys (A, i, e, v) are shortcuts for the common ones; the rare ones live only here.

            Analyze and identify

            • A queues the selection. The status line counts (analyzing 1/2) and the rows get their DR as each album finishes. Try it on "Unsorted demo", which has no DR yet.
            • i shows what MusicBrainz proposes as a diff. Fields that change are checked; space keeps or skips one, Enter applies. Nothing is written to the files, only to the library's own fields.

            Meters

            • On the fly, as in the TUI: m / M change the active panel's meter, + / - add or remove a panel (0 to 4), 1–4 choose the panel, c takes the meter colours from the cover. With 0 panels the cover takes the room.
            • The Meters button (or :meters) opens the picker with a live preview of each meter, for choosing without cycling.
            • It is the same list as the settings page (users.meters), just edited where the music is.

            Full screen: f

            • With meters: the meter panels fill the screen (1 full, 2 side by side, 3–4 in a grid), a small cover and the title row above, the progress line below. The active panel has an amber frame.
            • Without meters: a big centred cover with the title, artist, album, format, DR and findings under it, like the TUI and the web's expanded player.
            • Esc or f goes back. As in the TUI, browsing keys are off and the player and meter keys work. Tab picks the next panel. The button row at the bottom gives touch the same controls.
            • The @persist player and the one audio graph are unchanged: this is the existing expanded player with the new layout.

            Cover: P

            • P switches the cover between the real image and the pixelated mosaic, in the library dock and in full screen. Try it now.
            • It is remembered per user, with the theme as the default (pixelated only in Terminal). The Pixel button does the same on touch.
            • Only the display changes. The cover file and the cover search are untouched.

            Same keys as the TUI

            • space pause, , . seek, m M meter, + - panels, c cover colours, t T next / previous theme (Graphite is the new grey and coral one), f full screen, ? help. Move-to-folder moved to v, so that m is the meter key in both.
            • n p next and previous (p restarts the track after 3 s), as in the TUI, so new folder is N. L (loudness matching) is the web player's own, as today.

            Transport

            • Previous, play/pause and next sit under the progress line (and in full screen). Keys: p, space, n. p restarts the track when it is more than 3 s in, as in the TUI.
            • Click or tap the progress line to seek. , . jump 10 s. The playing row in the track list follows.

            Info on or off: I

            • The Info button sits with the other toolbar buttons (and in the full-screen row). It cycles three levels, and the choice is remembered per user: off, DR and all.
            • Off removes the DR column and the ! flags from the lists, and the format and findings lines from the dock and full screen. It leaves a plain library with only titles, years and times.
            • DR shows the DR column and the format line (MP3 · 32-bit / 48 kHz · DR9 (fair) · −10.9 LUFS). All adds the ! flags in the track list and the findings line (! Clipped, ! Peaks over 0 dBTP), or "no findings" / "not analysed yet".
            • Sorting by DR (s) is skipped while info is off. The line follows the playing track.
