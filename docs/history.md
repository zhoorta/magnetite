# Magnetite history

The long, dated log of what was built and checked, kept as it was written in `PLAN.md` until 2026-11-13. `PLAN.md` is now the short status; new detail goes in the topic docs (see `docs/README.md`), not here.

A web player where the look is the product: themes are one JSON bundle (palette, radius, font, default visualizer + params), visualizers are pluggable canvas modules, and playback never stops while you navigate.

## Positioning (decided 2026-10-08, revisit)

Library servers are a solved problem (Navidrome, Koel, Funkwhale). Feishin and Koel already ship palette themes and visualizers, so the gap is: themes as full bundles in a free shareable file, a polished fullscreen now-playing mode, and a PHP/Livewire option. Pitch the look, not the library.

Decided 2026-10-08: stay standalone, with its own thin library (scanner, covers, ALAC conversion). An OpenSubsonic client was considered and dropped for now (Feishin already covers it, and the scanner work would be thrown away); it could return later as an alternative track source behind the same player. Extracting the theme engine as a package stays an option.

## Next
- [x] Sample-accurate meters in an AudioWorklet (2026-10-08): `worklet/meter-processor.js` computes K-weighted LUFS (momentary 400 ms, short-term 3 s, integrated with the absolute and relative gates), true peak (4x oversampling, 49-tap windowed sinc), phase correlation (0.3 s) and the last 1024 L/R samples, and posts them about 60 times a second. New `lufs` and `stereo` inputs in the meter contract, and two meters: `goniometer` (vectorscope with afterglow plus correlation strip) and `loudness` (M, S, I with a -23 LUFS target tick, true peak per channel in red above -1 dBTP). 13 Node tests (`npm run test:js`) check the DSP against known values: stereo 1 kHz at -20 dBFS reads -20.0 LUFS, one channel only -23.0, gating ignores a silent tail, a fs/4 tone at 45 degrees reads 1.0 true peak while its samples only reach 0.707, correlation +1, -1 and about 0, at 44.1 and 48 kHz. In headless Chrome on a real loud track it read -9.3 LUFS momentary and -0.4 dBTP; four-meter CPU cost stays under 1 ms. Not checked: Safari (AudioWorklet is supported since 14.1), and the numbers against an EBU Tech 3341 test file or a reference meter
- [x] Third-octave analyser (2026-10-08): `third-octave` visualizer, 31 ISO bands 20 Hz to 20 kHz, segmented 3 dB steps, instant rise, 0.35 s release, peak marker that holds 1.5 s then falls 18 dB/s, scale -72 to -12 dB. A separate listening-only analyser with a 16384-point FFT (the 2048 one has bins wider than the lowest bands), band powers summed in `bands.js` and calibrated so a full-scale sine reads 0 dB. Measured in headless Chrome with an oscillator: full-scale 1 kHz, 997 Hz, 100 Hz and 5 kHz read 0.00 dB in the right band, -20 dB amplitude reads -20.00, the next band is at least 67 dB down (19.6 dB down at 40 Hz, where a band is only 9 Hz wide and the window's main lobe spills over). 6 more Node tests (band edges, power addition, silence). Cost: about 1.1 ms of CPU per frame while it is on screen, almost all of it the FFT

## Known risks

- Mobile Safari: strict `AudioContext` and background playback rules.
- Albums without an album-artist tag are grouped by title within their folder; a compilation split across folders becomes several albums.
- The scan runs synchronously from the command; move it to a queued job when the library page offers a rescan button.
- Gapless playback and crossfade need a second element; skipped for v1.
